# 设计语言

这是一个看管 Agent 工作的界面，不是聊天窗口。人大部分时间不看它，看的时候只想回答三个问题：它需要我吗？它做完了吗？它做了什么？所有设计决定都从这里出发。任何 Agent（Codex、ACP 上的其他实现）都用同一套语言。

## 四条原则

1. **注意力分三层，界面只有一个地方最响。**
   - 决定：需要人回答的事。全页唯一使用强调色的内容，而且一次只呈现一个。
   - 结果：Agent 交付的回答。最大的正文，满行宽。
   - 过程：看文件、跑命令、思考。安静、默认折叠、用次要文字色。
2. **回合是一件工作。** 人说的话在右侧的气泡里，这是所有人都熟悉的习惯，不改；智能体一侧是一条过程时间线，最后是结果和一行总结。

   一个回合从开始到结束只有一份列表：回复从第一个字起就在它最后的位置，回合结束时过程行只是折叠，不重画。屏幕上已有的内容不因状态变化而移动、换样式或丢掉选区和滚动位置；要动就得有明确的理由。

   约定俗成的东西不做新花样：消息左右、回车发送、输入框在下面。设计语言用在层次和细节上，不用在让人重新学习上。
3. **字体说明来源。** 人和 Agent 写的话用正文字体，机器执行和读取的东西（命令、路径、输出、Diff）一律等宽。
4. **颜色只表达状态。** 强调色只表示“需要你”，连发送按钮、开关、链接、选中标记都不用；“正在进行”用中性色的脉动。绿和红只表示增删和成败。结构靠明度和留白，不靠彩色，也尽量不靠线。
5. **图标只有一套、两种尺寸。** 全部来自 Lucide，路径写在 `src/ui/Icon.tsx`。能按的东西用 16px，行内的小标记（V 形箭头、对勾）用 14px，两种尺寸画出来的线一样粗。折叠箭头一律放在文字后面，这样折叠行和正文左边对齐。
6. **参考好作品，但结论自己下。** 遇到拿不准的细节，去看好的产品怎么解决（比如 ChatGPT 的 Work），想清楚为什么这样做，再决定我们怎么做。取思路和结构，不抄数值和外观：灰度是 hostc 自己的锌灰，强调色是 hostc 的橙。

手机是一等公民：人离开键盘时才最需要这个界面。决定和主要操作都在拇指能碰到的地方，触控目标不小于 44 像素。

## 文件夹

同一条链接可以在这台电脑的任何文件夹工作（`hostc codex --here` 只限当前目录）。侧栏按文件夹分组，每组可以折叠，顺序固定；会话留在它所属的文件夹里，不因为状态变化而移动。状态标在行尾固定的位置：转圈是运行中，橙点是需要你；文件夹折叠时，标在组标题上。每组显示最近几条，运行中和需要你的不会被藏起来。只有一个文件夹时，分组退回到按日期。权限按文件夹分别记住，没选过的文件夹一律先询问：在临时项目开了完全访问，不会带到别的项目。新建会话时在托盘里选文件夹，文件、变更、`@` 搜索和技能都跟随当前会话的文件夹。

## 输入区

写的内容和发送放在卡片里，加号在左，模型和发送在右。不常改的（权限、计划、分支）放在卡片下面的托盘里。

推理强度每次请求都可能调，所以是模型面板里最先看到的：一条滑杆，拖一下就好，原生 `input[type=range]`，键盘和读屏都能用。换模型多一步，点面板顶部那行再选。Fast 也在这个面板里。

## 变量

全部在 `src/ui/tokens.stylex.ts`，组件不写死任何值。

| 类别 | 档位 |
| --- | --- |
| 明度层级 | `canvas`（侧栏，最底）→ `bg`（工作区）→ `surface`（嵌入的块）→ `raised`（浮起的卡片）→ `overlay`（菜单、对话框） |
| 文字 | `text`（主要）、`muted`（次要）、`faint`（辅助，仍满足 4.5:1） |
| 字号 | `xs` 12、`sm` 13（元信息）、`md` 14（界面和过程）、`read` 15（阅读，手机 16）、`lg` 18、`display` 26 |
| 间距 | `xxs` 2、`xs` 4、`sm` 8、`md` 12、`lg` 16、`xl` 24、`xxl` 40 |
| 圆角 | `xs` 6、`sm` 8（控件）、`md` 12（卡片）、`lg` 16（输入框、对话框）、`xl` 20（手机底部面板） |
| 控件高度 | `control.sm` 28/36、`control.md` 32/44（斜杠后是触屏高度） |
| 动效 | `quick` 100ms（悬停）、`move` 180ms（出现）、`slow` 280ms（面板）；都用同一条减速曲线，减少动态效果时为 0 |

线只在区域之间用一根 `line`，卡片内部不再套线。阴影只给真正浮起来的东西（输入框、菜单、对话框）。

## 组件分层

先有 `src/ui` 再有页面。`src/ui` 不知道 Agent 是什么，`src/components` 把它们拼成这个产品。`/design` 路由列出所有基础件的所有状态，改基础件时先在那里看。

## 和 Agent 的边界

`src/components` 只认识 `src/harness/model.ts`：会话、回合、步骤、决定、能力。把某个 Agent 的协议翻译成这些概念，是 `src/harness/` 下适配器的事。组件里不允许出现协议类型。接新 Agent 时，写一个适配器，界面不用改。
